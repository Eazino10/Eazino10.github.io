SCADA-Style Wireless Sensor Network

A multi-microcontroller robust wireless system engineered for low-latency remote monitoring and physical actuation without reliance on traditional Wi-Fi infrastructure.

ESP-NOW ESP32 (S3/C3) Arduino UNO C/C++

01. Project Overview

In industrial and isolated environments, traditional Wi-Fi networks can be unreliable, power-hungry, or completely unavailable. This project bridges that gap by implementing a SCADA-like (Supervisory Control and Data Acquisition) architecture using local, low-overhead peer-to-peer communication.

The system comprises distributed sensor nodes that collect environmental data and transmit it instantaneously to central actuator nodes capable of triggering high-voltage or mechanical systems via relays. This was entirely prototyped on breadboards, allowing for rapid real-world testing of signal integrity and physical component interaction.

02. System Architecture & Hardware

Node Communication (ESP32)

Utilized ESP32-S3 and ESP32-C3 microcontrollers as the primary communicators. Their dual-core architecture (S3) and RISC-V efficiency (C3) handled data acquisition and wireless transmission seamlessly.

Actuation Node (Arduino)

An Arduino UNO served as the local logic controller for actuation, interpreting signals from the ESP network to drive mechanical outputs safely and deterministically.

Power Switching (Relays)

Integrated 5V Relay Modules to allow low-voltage microcontrollers to safely isolate and control higher voltage/current loads, simulating industrial control scenarios.

Prototyping

Extensive breadboard assembly and multimeter testing were conducted to verify logic levels, ensure sufficient current delivery to relays, and eliminate ground loops.

03. Protocol

The backbone of the system's speed is the ESP-NOW protocol. By bypassing standard Wi-Fi router association and DHCP handshake processes, ESP-NOW allowed the nodes to communicate using connectionless MAC-to-MAC packet transmission. This resulted in sub-millisecond latency and highly reliable data transfer over considerable distances.

04. Software & Tools

The entire firmware stack was written in C/C++ using the Arduino IDE.

  • Custom struct definitions for standardized packet payloads.
  • Non-blocking state machines (`millis()` based) for sensor polling.
  • Serial debugging and memory management.

05. Challenges & Solutions

ESP-NOW Protocol Instability

The Problem: Initially, establishing a stable connection between the ESP32-S3 (sender) and ESP32-C3 (receiver) proved difficult. Packets were dropping intermittently, and the peer registration process would frequently timeout.

The Solution

I performed step-by-step debugging of the microcontroller networking protocols. I discovered that the Wi-Fi mode must be explicitly set to WIFI_STA (Station Mode) before initializing ESP-NOW. Additionally, I implemented strict MAC address verification and ensured both microcontrollers were locked to the exact same Wi-Fi channel, which completely resolved the packet loss and stabilized the connection.

Voltage Logic Level Discrepancies

The Problem: During physical breadboard assembly, interfacing the ESP32 network output with the Arduino UNO actuator node and the 5V relay module resulted in erratic triggering. The relay would sometimes chatter or fail to latch completely.

The Solution

I used a multimeter to troubleshoot the voltage logic levels and found that the 3.3V logic signals from the ESP32 were insufficient to reliably drive the 5V components. I resolved this by routing the actuation logic through the Arduino UNO, which natively outputs robust 5V logic signals. I also introduced a dedicated power rail for the relay module to isolate the switching noise from the microcontrollers, ensuring clean, safe, and deterministic actuation.

05. Challenges & Solutions

Challenge: Relay Coil Power Draw

Issue: Activating multiple 5V relays simultaneously caused sudden voltage dips (brownouts) that triggered the Arduino UNO and ESP32 nodes to randomly reset.

Solution: Separated the logic power supply from the relay coil power supply. Implemented opto-isolated relay boards and added 470µF smoothing capacitors across the main power rails to handle transient current spikes.

Challenge: ESP-NOW Interference

Issue: High packet loss and increased latency were observed when operating the nodes in environments heavily saturated with active 2.4GHz Wi-Fi routers.

Solution: Modified the initialization firmware to scan the local RF environment during boot. The script now dynamically assigns the ESP-NOW communication protocol to the least congested Wi-Fi channel, ensuring robust data delivery.
