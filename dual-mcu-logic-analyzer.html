Dual-MCU Logic Analyzer & Signal Generator

A standalone embedded debugging workbench pairing a rotary-controlled multi-protocol signal generator (ESP32-D0WD-V3) with a 4-channel pocket logic analyzer and real-time protocol decoder (ESP32-S3).

ESP32-S3 ESP32-D0WD-V3 I2C / UART / PWM / SPI ST7735 & SSD1306 C++ / Arduino Core v3

01. Project Overview

Debugging embedded communication buses typically requires expensive benchtop oscilloscopes or PC-tethered USB logic analyzers. To create a portable, self-contained alternative, I engineered a dual-microcontroller workbench that decouples deterministic signal generation from high-speed digital waveform capture.

On one side, an ESP32-D0WD-V3 serves as an interactive target stimulus generator, outputting live I2C display frames, UART telemetry packets, simulated SPI sensor bursts, and adjustable LEDC PWM square waves controlled via a KY-040 rotary encoder menu. On the other side, an ESP32-S3 acts as a 4-channel pocket logic analyzer, capturing logic edges via single-cycle GPIO register reads and rendering color-coded waveforms alongside decoded I2C addresses, UART ASCII text, and PWM frequency/duty telemetry on a 1.44-inch ST7735 TFT display.

02. System Architecture & Hardware

Target Signal Generator (ESP32-D0WD-V3)

Generates four simultaneous bus signals across non-conflicting GPIOs: I2C (SDA GPIO 2, SCL GPIO 4) driving a 128×64 SSD1306 OLED, PWM (GPIO 18), UART TX0 (GPIO 1), and bit-banged SPI bursts (CS 13, SCK 19, MOSI 27).

4-Channel Analyzer Node (ESP32-S3)

Samples contiguous input pins GPIO 4, 5, 6, and 7 (CH0–CH3) in a single atomic register read (GPIO.in >> 4), timestamping transitions to microsecond precision via esp_timer_get_time().

Dual-Display Telemetry & UI

The generator's SSD1306 OLED displays live frame counts and active menu parameters, while the S3's 1.44" ST7735 TFT (40 MHz hardware SPI) uses an off-screen GFXcanvas16 framebuffer for flicker-free waveform rendering.

Tactile Hardware Controls

A KY-040 rotary encoder (CLK 5, DT 15, SW 23) lets the user cycle between Baud Rate (4800–115200 bps), PWM Frequency (500–5000 Hz), and Duty Cycle (10%–90%) live. On the S3, the BOOT button handles single-tap HOLD/LIVE freeze and long-press 1x/4x/16x timebase zoom.

03. Real-Time Protocol Decoding

Rather than displaying raw square waves alone, the ESP32-S3 analyzer runs multi-protocol software decoders over every 512-sample capture buffer. It detects I2C START/STOP conditions to extract the 7-bit slave address (0x3C), measures minimum pulse widths on CH3 to auto-detect baud rate and reconstruct 8N1 UART ASCII characters, and averages cycle periods on CH2 to compute live PWM frequency and duty cycle percentages.

04. Software & Tools

Both firmwares were developed in C++ targeting the ESP32 Arduino Core v3.0+ in the Arduino IDE.

  • Migrated PWM generation to Core v3 ledcAttach() and ledcWrite() APIs.
  • Non-blocking millis() task scheduler for zero-latency rotary encoder polling.
  • Free-running oscilloscope sweep tuned to a 500 ms refresh cadence.

05. Challenges & Solutions

Blocking Loop Latency & Missed Encoder Detents

The Problem: Initial firmware revisions used a delay(200) call at the end of the main loop to pace UART and OLED updates. Because the CPU stalled for 200 ms every cycle, rapid turns on the KY-040 rotary encoder went unregistered and failed to update the PWM output or OLED cursor.

The Solution

Refactored the target generator into a non-blocking millis() state machine. Polling handleEncoder() continuously at full loop speed while gating bus bursts to 200 ms intervals restored instant mechanical responsiveness and live OLED feedback.

Balancing Trigger Arming vs. Oscilloscope Sweep Pacing

The Problem: Edge-triggered capture sweeps with a 1500 ms display hold felt sluggish during live frequency tuning, whereas stripping the trigger wait with a 150 ms refresh rate caused the waveforms to cycle too rapidly to read telemetry comfortably.

The Solution

Implemented a free-running immediate acquisition sweep paired with a tuned 500 ms refresh interval (REFRESH_INTERVAL_MS 500) and a 5 ms static-bus timeout. This eliminated arming stalls while maintaining a readable 2 Hz oscilloscope cadence alongside instant single-button frame freeze (HOLD).

ESP32 Arduino Core v3.0+ LEDC API Migration

The Problem: Compiling legacy ledcSetup() and ledcAttachPin() calls under ESP32 Arduino Core v3.x triggered scope compilation errors due to breaking peripheral API changes.

The Solution

Updated the PWM driver to use the unified ledcAttach(PWM_PIN, freq, 8) and pin-addressed ledcWrite(PWM_PIN, dutyVal) functions, enabling dynamic runtime reconfiguration of both frequency and duty cycle.
